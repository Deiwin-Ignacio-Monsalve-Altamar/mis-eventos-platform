# mis-eventos-platform
Full-stack event management application built with Flask, React, PostgreSQL, and Docker, following Clean Architecture and SOLID principles.

## Database and migrations

For local development, create `.env` from `.env.example` only when `.env` does not already exist. Run this from the repository root; it preserves any existing local configuration:

```sh
if [ ! -f .env ]; then
  cp .env.example .env
fi
set -a
. ./.env
set +a
```

Generate a signing key, place it in `.env` as `JWT_SECRET_KEY`, then source the file again. Do not commit `.env`:

```sh
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
set -a
. ./.env
set +a
```

The Flask application and Alembic both use `DATABASE_URL`; when it is unset, they use the same local PostgreSQL URL configured by the backend. From the repository root, enter `backend` to run migrations:

```sh
cd backend
poetry run alembic upgrade head
poetry run alembic revision --autogenerate -m "describe schema change"
```

Review autogenerated revisions before applying them. The initial schema migration creates users, events, event sessions, speakers, registrations, and the event/session speaker associations.

## Authentication

Register with `POST /api/v1/auth/register` using `email`, `password`, `first_name`, and `last_name`. Log in with `POST /api/v1/auth/login`; the API sets an expiring HttpOnly access cookie and returns only the public user profile. Send the cookie to `GET /api/v1/auth/me` to retrieve the authenticated user's public profile. Passwords are stored as SHA-256 hashes because the technical challenge explicitly requires `hashlib.sha256()`. Plain SHA-256 is fast and is not recommended for production password storage; use a dedicated password-hashing algorithm for production systems. Use `JWT_COOKIE_SECURE=true` behind HTTPS.

Event creation and editing endpoints are not part of SCRUM-9. Apply and test authentication and authorization protection when those endpoints are implemented in SCRUM-10.
